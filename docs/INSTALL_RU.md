# Установка «Мишки»

## 1. Требования
- Waveshare ESP32-S3 AUDIO с подключённым динамиком и микрофонами платы.
- ESP-IDF 5.5.6; `idf.py set-target esp32s3`.
- Home Assistant с настроенным голосовым конвейером Assist (STT и TTS).
- MQTT-брокер, доступный ESP32 и Home Assistant.

## 2. Сборка прошивки
```powershell
cd firmware
idf.py set-target esp32s3
idf.py build
idf.py -p COM11 flash monitor
```
Укажи свой COM-порт. Первая установка через USB; для дальнейших обновлений используй веб-панель OTA.

Параметры аппаратной платформы: ES7210 (RX GPIO15), ES8311 (TX GPIO16), общие BCLK GPIO13 и WS GPIO14, WS2812 GPIO38. **Не меняй общие BCLK/WS без пересмотра всей I²S-архитектуры.**

## 3. Wi-Fi, MQTT и Assist
Открой веб-интерфейс устройства по полученному IP и укажи Wi-Fi, MQTT и параметры Assist. Для WebSocket используется `ws://<HA-IP>:8123/api/websocket`. Долгосрочный токен HA вводится только в локальном веб-интерфейсе Мишки; не помещай его в исходники, issues, скриншоты или логи.

Для сохранения параметров Assist веб-интерфейс отдельно запрашивает **пароль OTA**. После сохранения устройство перезагружается.

## 4. Пользовательская интеграция Home Assistant
Скопируй каталог `custom_components/mishka_speaker/` в `/config/custom_components/mishka_speaker/` и перезапусти Home Assistant. Настрой интеграцию через **Настройки → Устройства и службы**; при наличии MQTT Discovery диагностические датчики объединяются с устройством «Мишка».

## 5. Проверка
- Слово «Мишка» вызывает вспышку WS2812; состояние Assist переходит в `listening`.
- Команда «Мишка, включи ночник» достигает HA и выполняется.
- Синтезированный ответ воспроизводится через ES8311.
- После ответа радио восстанавливается, обычный LED-эффект возвращается.
- Кнопка BOOT (GPIO0) отключает/включает микрофон.

## 6. Диагностика
- `esp_ws_handshake_status_code=403`: проверь доступность HA и блокировку IP в `/config/ip_bans.yaml`, исправив первопричину.
- `auth_invalid`: проверь токен, вводя его локально на Мишке.
- `Received binary message for non-existing handler`: убедись, что PCM передаётся только при активной сессии STT и с действительным ID бинарного обработчика.
- При OTA с rollback новая прошивка требует подтверждения после успешного тестирования.

## Безопасность
Не публикуй `sdkconfig`, NVS, реальные пароли, токены, дампы логов с секретами и локальные резервные копии.
